# Tool access

Use a file-aware assistant, authorized web research, native image generation,
Python 3.10 or newer, and FFmpeg/ffprobe for local checks. Run from your configured
workspace; the maintained tools are in `scripts/`. An authorized research inbox
is optional when public editions provide a workable fallback.

For publication, use your own Postiz CLI authentication and private `x` and
`linkedin` integration aliases. Store secrets and account maps outside Git.
Check live destination identities and route-specific online readiness before
uploading. A generic tool-ready flag does not prove the account can publish.

The portable template uses Postiz only. Browsers can independently verify public
results. Any alternative creation route needs its own explicit authority and
duplicate checks. It is not an automatic fallback after a timeout.

The legacy badge tool remains for historical packages. New generated images use
the schema-3 asset validator and native scene-integrated marks. Retention is an
optional, separately authorized operation on dated delivery copies only.
